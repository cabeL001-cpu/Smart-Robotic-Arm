### 2.1 11-22 的固件与链路改动

1. 板上固件一度是旧底盘草图，`ARM` 回复 `ERR DURATION`；已用 `arduino-cli` 重烧 `/tmp/qoder_calib/move`：
   - `SHOULDER_PIN = 18`（A4）、`ELBOW_PIN = 10`；
   - `arm_limits.h` 仍为 500–2500 µs 的临时放宽值；
   - 新增 `ARM OFF`：对两路舵机调用 `detach()`，回复 `OK ARM OFF`。蓝牙链路没有 DTR 复位，脚本结束必须显式释放，避免舵机长时间锁在最后一条脉宽上。
2. **串口回显陷阱**：`/dev/ttyACM0` 与 `/dev/rfcomm0` 的行规程可能开着 ECHO，Uno 的回执会被原样送回自己的 RX，形成 `ERR DURATION` 或 `SONAR ...` 的无限回环。所有串口操作前先执行：
   ```sh
   stty -F /dev/ttyACM0 raw -echo    # 蓝牙时为 /dev/rfcomm0
   ```
3. 蓝牙点动脚本 `/tmp/qoder_calib/tap_bt.py`：发 `ARM 肩 肘`，保持 0.5 s，再发 `ARM OFF`。每次只动一小步，不长时间顶限位。
4. 校验固件时用不动舵机的命令：`ARM 400 1450` 应在 attach 前被拒绝为 `ERR ARM`，`ARM OFF` 回复 `OK ARM OFF`，`STOP` 回复 `OK STOP`。

## 3. 遇到的问题与处理

1. **本地仓库与远端仓库不一致**
   - 远端缺 `vision/printed.py` 和 `vision/scan.py`，无法稳定识别印刷角标。
   - 处理：用本地新版 `Agents/vision` 的副本在 `/tmp/qoder_calib` 下运行，不改远端仓库。

2. **`ARM` 一开始被拒绝（`ERR ARM CALIBRATION`）**
   - 原因：`arm_limits.h` 全为 0。
   - 处理：刷临时放宽限位固件后回复 `OK ARM`。

3. **HC-05 回复偶尔为空**
   - 现象：发 `ARM ...` 后读不到 `OK ARM`，但舵机实际执行了。
   - 原因：半双工链路开头字节丢失。
   - 处理：不要因回复为空就盲目重发；用舵机动作、相机或目视确认。

4. **顶部相机源选错**
   - `CAM=0` 对应 C170，打不开；顶部 C270 是 `/dev/video2`。
   - 处理：所有采集都指定源 `2`；`devices.env` 尚未修正（待办）。

5. **棋盘角标检测不稳定**
   - 印刷角标在部分帧只识别出 1 个，`fit_plane` 需要至少 2 个，导致测量返回 `None`。
   - 处理：
     - 对灰度图做 CLAHE（clipLimit 2.0）；
     - 多帧、多预处理变体合并角标；
     - 用一次质量较好的采集拟合出固定单应，后续只测末端标签。
   - 局限：末端标签在白色棋盘上方、大角度斜视或被大臂遮挡时仍会检测失败。

6. **肩部一直不动**
   - 现象：1450/1500/1700/2100 µs 都没有位移，`OK ARM` 正常。
   - 原因：肩部信号实际插在扩展板 **A4**，固件驱动的是 D13。
   - 处理：改接到 D13 后肩部恢复动作（1500 µs 即转到最大限位方向）。

7. **肩部剧烈抖动、动作缓慢**
   - 现象：改线后 1500 µs 冲到最大限位；1400 几乎不动；1200 持续抖动；1000 边抖边小幅顺时针转；1300 又回到最大限位并剧烈抖动。
   - 原因：舵机排针的 V 针从 **Uno 5V** 取电，而独立电源只有 **3.7 V**，没有真正给舵机供电。MG995 带整条大臂负载时电流远超 Uno 5V 能力，电压跌落造成堵转、抖动和“假限位”。
   - 处理：**未解决**，需外接 5–6 V、≥3 A 电源，见第 6 节。

8. **坐标系容易混**
   - 设计图坐标系：棋盘左下角为 (50, 50)，肩部名义位置 (-100, 150)，格 4 为 (150, 150)。
   - 相机/棋盘坐标系：棋盘左下角为 (0, 0)，肩部名义位置 (-150, 100)，格 4 为 (100, 100)。
   - 本次所有毫米坐标统一用**棋盘坐标系**。

9. **USB 打开串口会复位 Uno**
   - 台架调试时每次重新打开 USB 串口都可能复位；应复用同一连接，无线链路不受影响。

10. **板上固件缺少 ARM 分支**（11-22）
    - 现象：`ARM ...` 回复 `ERR DURATION`，舵机没有 attach。
    - 原因：Uno 上运行的是旧底盘草图，不是 11-21 的临时 ARM 固件，且这份草图没有 `ARM` 处理。
    - 处理：确认接线后重烧 `/tmp/qoder_calib/move`，用 `ARM 400` 得到 `ERR ARM` 作为版本校验。

11. **串口自激回环**（11-22）
    - 现象：串口持续刷 `ERR DURATION` 或 `x72=NA ...`，发一行会无限回显。
    - 原因：tty 行规程的 ECHO 把 Uno 的回复送回 Uno 的 RX；蓝牙 rfcomm 同理。
    - 处理：先 `stty -F <端口> raw -echo`，并避免用 `cat` / `printf` 直接测试。

12. **USB 与舵机抢 5V**（11-22）
    - 现象：USB 连着树莓派时动臂，出现抖动、堵转和树莓派 `Undervoltage detected`。
    - 处理：动臂时拔掉 USB，Uno 与舵机由外部 5–6V 供电；USB 仅用于烧录和不动舵机的校验。

## 4. 已建立的标定与测量关系

### 4.1 棋盘与角标

- 印刷角标 `printed5` 为 15 mm 黑边方块，中心位于棋盘坐标：
  - ID 0 = (7.5, 7.5)（左下）
  - ID 1 = (192.5, 7.5)（右下）
  - ID 2 = (7.5, 192.5)（左上）
  - ID 3 = (192.5, 192.5)（右上）
- 当前相机画面里棋盘约顺时针转 12°，四个码在图像中的位置为：
  - 图像左上 = printed5 0
  - 图像右上 = printed5 2
  - 图像左下 = printed5 1
  - 图像右下 = printed5 3
- 用 3–4 个角标拟合的单应，重投影 RMS 约 **0.97–1.16 px**。

### 4.2 末端标签与角度

- 末端标签 `36h10/100` 贴在末端，标签平面与棋盘平面平行。
- 高度不同的平行平面经单应投影后是**相似变换**，角度不变，所以“标签在棋盘坐标里的朝向角”可以直接用来测小臂转角。
- 标签在图像里被大臂遮挡或落在白色棋盘上且斜视时，检测会失败。

### 4.3 肘部脉宽—角度关系（已确认）

基准姿态：肩部未接通信号、停在最小角度，肘部 1450 µs。

| 肘部脉宽 (µs) | 末端标签位置（棋盘 mm，tip_height=0） | 标签朝向 (°) | 样本数 | 备注 |
| --- | --- | --- | --- | --- |
| 1450 | (205.6, 62.0) | 106.5 | 3 | 基准 |
| 1450（复测） | (205.3, 62.1) | 107.1 | 1 | 重复性约 0.3 mm / 0.7° |
| 1500 | (215.2, 64.0) | 103.2 | 23 | |
| 1550 | (220.7, 64.0) | 103.5 | 16 | |
| 1800 | (328.5, 55.4) | 76.6 | 18 | 顺时针 |
| 1200 | — | — | — | 末端标签斜视/白底，检测失败 |
| 1050 | (75.5, -32.1) | 142.5 | 29 | 逆时针 |
| 650 | — | — | — | 标签被大臂遮挡；用户目视确认相对 1450 约逆时针 90° |

结论：

- **脉宽增大 = 顺时针（CW）；脉宽减小 = 逆时针（CCW）。**
- 斜率约 **9–11 µs/°**，初值取 **10 µs/°**。
- 以 1450 µs 为 q=0 基准：
  - `us ≈ 1450 − 10 × q`（q 为逆时针为正，单位度）
  - 90° 逆时针对应约 550–650 µs；实测 **650 µs ≈ 90°**，与目视结果一致。
- 脉宽下限受固件 attach 范围 500 µs 限制，1450 → 500 约只剩 95°，正好贴着 90° 需求，最终零位可能需要重新选。

> 注意：表中的毫米位置使用 `tip_height_mm = 0` 投影，是“棋盘平面上的视在位置”。末端实际高于棋盘时，位置会被放大；角度不受影响。绝对值在完成高度标定前不能当作真实 XY。

### 4.4 肩部标定（11-22 实测）

条件：外部供电、HC-05（sjtu013）RFCOMM 链路、肩部信号接 D13；每步保持 0.5 s 后立即 `ARM OFF`。角度用量角器，0° 取大臂机械最小位置方向。

| 肩部脉宽 (µs) | 量角器角度 (°) | 备注 |
| --- | --- | --- |
| 500 | ~50 | 单点，读数约 ±5° |
| 600 | 60 | 同向扫描 |
| 900 | 85 | 同向扫描（另一次单点读到约 90） |
| 1200 | 110 | 同向扫描 |
| 1400 | 130 | 顶到机械限位，抖动 |

- 方向：**脉宽增大 = 逆时针（向最大角度）**。
- 取 600/900/1200 三个未被限位挡住的点拟合：斜率 **12 µs/°**，`θ = (p + 120) / 12`，即 `zero_us = -120`、`us_per_degree = 12`。零角在当前脉宽行程之外，属于文档允许的负截距情况。
- 机械最大角度约 **130°**、最小约 **0°**（仅记录机械行程；工作上限取 100°，不驱动到 130°）。1400 µs 一步顶着限位，130° 与线性外推 126.7° 之差属于读数误差。
- 中段各步转动顺畅，只在顶住限位后抖动，说明舵机与供电正常。
- **工作范围（11-22 晚定稿）：10–100°，100° 是运行上限，不动 130° 机械止挡。** 受舵机下限约束，实际可执行 **400–1080 µs → 43.3–100°**；400 µs 实测定为下限。
- 低段实测：100 µs 几乎无反应，400 µs 动作正常 → 400 µs 写进固件作为 `SHOULDER_MIN_US`，100 µs 以下不再尝试。
- 10–43.3° 需要重装舵盘：肩盘顺时针拨 4 齿（约 57.6°）后 10°≈691 µs、100°≈1771 µs（上限需放宽到约 1780 µs）。不重装则 10° 不可达。
- **Servo 库陷阱（11-22 晚发现）**：`attach(pin, 0, 1080)` 会把 `(544-0)/4=136` 存进 `int8_t` 溢出成 -120，实际 `SERVO_MIN` 变成 1024 µs，导致 0–1024 µs 的指令全部被钳到 1024 µs（约 95°），大臂表现为“不动”。该库可表示的最小 `min` 是 **36 µs**；固件因此用 `attach(SHOULDER_PIN, SHOULDER_MIN_US, 2500)` 并在校验里拒绝 `<36`。
- 角度基准：量角器 0° 与关节角 0° 取同一条线（大臂最小位置方向）。后续顶摄标定基座 +X 时沿用这条线，`base_yaw_deg` 与之保持一致。
- `arm.json` 肩部取 `angle_at_max_deg=100`、`retreat_sign=-1`、`margin_deg=0`、`zero_us=-120`、`us_per_degree=12`、`min_us=400`、`max_us=1080`；`geometry.shoulder_limit_deg=100`。注意 `ServoCalibration` 目前校验 `min_us >= 500`，需要放开下限才能导出。

> 旧结论（供电不足时 1000–1500 µs 的抖动、1500 µs 大幅转动等）已被上表取代，不再作为标定依据。

### 4.5 基座位置的初步估计

- 从一帧俯视图目测肩部转轴像素约 (375, 295)，投到棋盘坐标约 **(192.5, −97) mm**。
- 与名义值 (-150, 100) mm 差距很大，说明机器人和棋盘的相对摆放与设计图不同。

- 末端到该估计转轴的距离约 156 mm，在 97–333 mm 的可达范围内。

## 6. 下一步计划

### 6.0 先解决供电（必须）

1. 断电后，把舵机排针的 **V(+)** 从 Uno 5V 断开。
2. 用 **5–6 V、≥3 A** 的电源给两路舵机供电；3.7 V 单节电池需升压到 6 V 并保证电流。
3. 电源 **GND 与 Uno GND 共地**；Uno 仅负责逻辑与信号；VOUT 保持空载。

## 7. 操作要点与安全

- 固件协议：`ARM <肩部us> <肘部us>\n`、`ARM OFF\n`；回复 `OK ARM`、`OK ARM OFF`、`ERR ARM`、`ERR ARM CALIBRATION`。
- 串口：9600 8N1；HC-05 `/dev/rfcomm0`；回复可能丢失但指令生效。操作前先 `stty -F <端口> raw -echo`，防止回显自激。
- 动臂时拔掉 USB：USB 会与舵机抢 5V，造成欠压抖动和树莓派复位。USB 只用于烧录与不动舵机的校验。
- 台架 USB 串口每次打开可能复位 Uno，连续操作要复用连接。
- 扫脉宽时避免长时间停在机械限位（堵转电流大、舵机发热）。
- 舵机电源改造前必须断电，热插拔 V/G 有烧板风险。
- 末端标签被大臂遮挡或落在白纸上时，顶摄不可用，改用目视确认。

### 8.2 蓝牙链路排查过程

1. `rfcomm show 0` 显示通道 `closed`，说明只有绑定没有会话。
2. `rfcomm release 0` 以 `mooc` 执行被拒（需要 root）。
3. 旧 tty 未释放，`rfcomm connect 0` 报 `Address already in use`；换 `rfcomm1` 也建不出节点。
4. 改用 **Python RFCOMM socket**：

   ```python
   import socket
   link = socket.socket(socket.AF_BLUETOOTH, socket.SOCK_STREAM, socket.BTPROTO_RFCOMM)
   link.connect(("00:20:04:BE:0C:00", 1))   # sjtu001
   link.sendall(b"STOP\n")
   ```

   不需要 root、不需要 tty 节点，也不受 tty 回显影响。
5. socket 连接后能持续收到 Uno 的超声波调试，但所有命令都没有回执 → 单向链路，问题在 HC-05 的 `TXD → D0`。

### 8.3 操作坑（不要再踩）

- **不要用 `pkill -f arm_link.py`**：模式会匹配到 SSH 命令自身，把会话杀掉。用 `ps -p <PID>` 确认后显式 `kill <PID>`。
- **打开 USB 串口后等约 2.2 s 再发命令**：Uno 的 bootloader 需要 1.5–2 s，0.3 s 时命令被丢，表现为“无回执”。
- **`rfcomm release` / `rfcomm connect` 需要 root**；普通用户只能配对，不能管理 rfcomm tty。
- **USB 数据线不要插在 Uno 上动臂**：既抢串口，也抢 5V。
- **关闭 USB 端口会复位 Uno**：相当于释放舵机；蓝牙没有这个副作用，必须靠 `ARM OFF`。
- **HC-05 与板载 USB 串口共用 D0/D1**：烧录前必须拔下模块，否则报 `not in sync`。
- **A4 是 I2C SDA**：临时固件把肩部放在 A4（D18）只是沿用 11-22 的接线；一旦 attach 舵机，A4 被 Servo 占用，SR09 的 I2C 会受影响。正式固件应回到 D13 或另选引脚。
