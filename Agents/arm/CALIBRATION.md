# 机械臂标定与九宫格到位

目标是让指尖在指定格心 **6.7 mm 以内连续保持 2 秒**。现场需要保存三样东西：本车两轴的 `arm.json`、由它生成并烧入 Uno 的限位，以及顶摄相对肩轴的 `rig.json`。以下命令供现场操作，从仓库 `Agents/` 目录运行。`CFG`、`CAM`、`UNO_PORT` 使用本车部署配置。[接线与环境](../DEPLOY_RASPBERRY_PI.md) · [接口和返回值](../API.md)

## 1. 建立实物基准

1. 支撑两段连杆，断开轮、舵机和 Uno 电源。确认肩部信号接 **D13**，肘部接 **D10**，两台 MG995 用容量适合负载的外部稳压电源，电源负极与 Uno 共地。扩展板 D10 对应的绿色 `VOUT` 保持空载。运行时 Uno 经 HC-05 通信。
2. 在框架上画出基座 +X 和正转箭头。从上往下看，逆时针为正。记大臂从肩轴指向肘轴的方向角为 `a`，小臂从肘轴指向实际指尖的方向角为 `b`。肩角 `q1` 是 `a` 相对基座 +X 的角度，肘角 `q2` 是 `b−a` 归一到 ±180°。两杆同向伸直时肘角为零。拍照时镜头正对运动平面，并在画面内放标尺。
3. 量肩轴至肘轴、肘轴至指尖在运动平面内的距离。图纸名义值分别为 152 mm、212 mm。将实测值写入 `geometry.upper_mm` 和 `geometry.forearm_mm`。指尖若偏离末杆中心线，需要先确定实际的末杆指向和角度基准，使运动学与视觉观察同一个点。
4. 利用已观察到的机械最大姿态，读两根连杆的角度，分别填写 `angle_at_max_deg`。**肩部卡住时先断电、支撑并卸下连杆检查干涉。不要通电顶住止挡，也不要继续扳舵盘寻找端点。** 修复后在可自由活动的范围内观察从最大位置退回的方向：几何角减小填 `retreat_sign=-1`，增大填 `1`。肩部照片无法给出肘部限位，也不能直接给出脉宽。

两轴都只使用从机械最大位置退回的 90°。代码在两端各留 `margin_deg`（默认 3°），再与图纸肩 ±85°、肘 ±135° 和实测脉宽取交集。若中间另有连杆碰撞，缩小安全范围或改变装配，重新标定。机构检查时同时观察两轴组合以及线束。

## 2. 标定每轴的脉宽

在已知安全初始脉宽处开始。可用已有可靠记录，或卸去连杆负载，在舵盘装配基准已作记号的台架上使用能显示微秒数的测试器。每次只量一个轴，取机械行程**内部**两个相距较远的位置，再取一个中间点复核。各点记录同一条基准线的几何角。

| 关节 | 最大处几何角 / 退回符号 | 第一组 (µs, °) | 第二组 (µs, °) | 中间点实测 (µs, °) | 可用脉宽下限、上限 |
| --- | --- | --- | --- | --- | --- |
| 肩 D13 | | | | | |
| 肘 D10 | | | | | |

设两个数据点为 `(p1,q1)` 和 `(p2,q2)`。计算 `us_per_degree=(p2−p1)/(q2−q1)`、`zero_us=p1−q1×us_per_degree`。允许负斜率，几何零角可在可用行程以外。用中间角计算预测脉宽，与实测比较，再从相反方向接近同一点检查回差。如果同一脉宽的方向、角度或重复性不稳定，先处理舵盘松动、供电或机构卡滞。

在部署配置目录创建 `arm.json`。下例的 `null` 均须替换为实测数，`retreat_sign` 为 ±1。两轴各自的 `min_us`、`max_us` 取实测安全边界，软件接受的外边界为 500 至 2500 µs。保留已有实车文件的备份。

~~~json
{
  "geometry": {"upper_mm": 152, "forearm_mm": 212, "base_x_mm": -100,
               "base_y_mm": 150, "base_yaw_deg": 0},
  "shoulder": {"angle_at_max_deg": null, "retreat_sign": null, "margin_deg": 3,
               "zero_us": null, "us_per_degree": null, "min_us": null, "max_us": null},
  "elbow": {"angle_at_max_deg": null, "retreat_sign": null, "margin_deg": 3,
            "zero_us": null, "us_per_degree": null, "min_us": null, "max_us": null}
}
~~~

`arm --cell` 采用图纸工位。棋盘左下在图纸坐标 (50,50) mm，图纸名义肩轴在 (−100,150) mm；同一肩轴在**棋盘系**为 (−150,100) mm。格 4 在棋盘系为 (100,100) mm，在图纸系为 (150,150) mm。使用固定工位的开环调用时按实际工位填写 `geometry.base_x_mm/base_y_mm/base_yaw_deg`。视觉闭环会按当前画面求肩轴的位置和方向。

## 3. 同步树莓派和 Uno 的限位

1. 在负责烧录的那份源码内放好同一份实测 `arm.json`。先预览一个已知行程内的关节姿态，然后生成头文件。预览会显示计划输出而不发命令。
2. 支撑连杆，关闭负载电源，断电拔下 HC-05，再用 USB 从烧录机写入完整 `move` 草图。成功后拔 USB，断电装回 HC-05，恢复供电。运行机继续使用这一份 `arm.json`。具体上传端口和命令见[烧录指南](../DEPLOY_RASPBERRY_PI.md#4-将合并固件烧录到-uno)。
3. 把两轴放在已知安全的起始姿态，接回负载。在当前实测角附近小幅点动，一个轴保持当前角度，另一个轴小幅改变。记录正方向、实测角和回差，再交换两轴。`OK ARM` 表示 Uno 接受两路输出。`ERR ARM CALIBRATION` 表示固件没有可用限位，`ERR ARM` 表示至少一路脉宽被拒绝。

~~~bash
export CFG="$HOME/.config/smart-robotic-arm"
source "$CFG/devices.env"
read -r -p "已量好的行程内肩角、肘角（度，以空格分隔） " Q1 Q2
python -m arm --config "$CFG/arm.json" --joints "$Q1" "$Q2" --dry-run
python -m arm --config "$CFG/arm.json" --export-limits move/arm_limits.h
# 完成上文的编译、烧录、恢复蓝牙后，在静止工位执行
python -m arm --config "$CFG/arm.json" --joints "$Q1" "$Q2" --port "$UNO_PORT"
~~~

## 4. 标定顶摄、棋盘和指尖

把车停在计划使用的工位，固定底盘，使用随车下视的 `CAM`。车头看墙标的 `FRONT_CAM` 另有一份标定。九宫格外边应为 200 × 200 mm，格号由左下 0 向右递增，上排为 6、7、8。确认棋盘平整且方向正确。实物印刷板的四角由 `printed5` 识别，旧模板使用 36h11 / 0–3。当前角标尺寸模型分别为 15 mm、20 mm。先量黑框外沿与棋盘边长，缩放错误时先修正实物或模型。[棋盘与相机说明](../vision/README.md)

1. 用 `vision.scan top` 看能否稳定识别棋盘，尽可能让四角可见。把末端标签平贴在与棋盘平行的平面上，默认家族 `36h10`、ID `100`。
2. 在 `$CFG/mount.json` 写实际 `image_size=[宽,高]`、`height_mm`（顶摄光心到棋盘平面，约 1.5 m，填毫米实测）、`tip_height_mm`（棋盘到末端标签）、`tip_offset_mm=[向标签右,向标签上]`（标签中心到真实指尖）。按标签印刷方向量偏移。摄像头倾斜时，记录光心铅垂落点在去畸变图像的 `nadir_px`。若有本镜头本分辨率的内参与畸变，将 `camera_matrix`、`distortion` 一并填入。[镜头内参采集方法](../move/CALIBRATION.md#3-标定前摄内参与安装位姿)
3. 在地面标出肩轴铅垂点。以棋盘左下为 (0,0) mm，量该点 `BX BY` 和基座 +X 对棋盘 +X 的逆时针角 `YAW`（度）。固定底盘，画面内含足够棋盘角标，执行下面的 `--save-mount`。程序保存肩轴及其正前方 100 mm 两点的投影像素。之后车辆换位置时，从同一台顶摄的新画面恢复基座。顶摄或肩轴相对车架移动后须重做。

~~~bash
python -m vision.scan top --source "$CAM" --config "$CFG/mount.json" --frames 15
read -r -p "棋盘系内肩轴 X、Y（毫米）及基座 +X 朝向（度） " BX BY YAW
python -m vision.align --source "$CAM" --config "$CFG/mount.json" \
  --base "$BX" "$BY" "$YAW" --save-mount "$CFG/rig.json"
python -m vision.arm --source "$CAM" --config "$CFG/rig.json" --cell 4
~~~

将指尖置于几个独立量好的位置，看只读输出中的 `tip_mm`、`target_mm` 和 `error_mm`。从不同臂姿检查同一点。若各处都有固定偏移，检查标签中心到指尖偏置。误差随离画面中心的距离增大时，核对内参、标签高度和铅垂落点。`measurement: null` 时检查棋盘及末端能否同帧识别。结束只读进程后再进入闭环。

## 5. 在停靠工位完成任务并记录

先选基座可达、连杆沿途无干涉的一格。在图纸对齐工位可用 `--dry-run` 预览图纸逆解。在任意停靠工位，使用实测的 `rig.json` 和实时画面执行 `vision.align`。导航返回的位置并未约束最终朝向，每个工位都要核对肩轴相对棋盘的方向、可达格和顶摄视野。命令行分别运行时先正常结束导航进程，释放 Uno 串口。

~~~bash
python -m arm --config "$CFG/arm.json" --cell 4 --dry-run
python -m vision.align --source "$CAM" --config "$CFG/rig.json" \
  --arm-config "$CFG/arm.json" --port "$UNO_PORT" --cell 4
~~~

闭环只在同时看到棋盘和指尖时发两轴指令。默认每次等 0.6 s 后再修正，最多 10 次、观测总时限 20 s。`error_mm < 6.7` 且连续满 2 s 才通过，观测缺失、超限或相邻帧间隔超过 0.5 s 会打断计时。若报不可达，记录工位、格号和当前基座方向，在容许区域调整停靠姿态再量。放宽关节限位会使已测的安全区间失效。

每个需要的工位逐格填写下表。用与视觉标定独立的标尺或格心定位纸测实际偏差，保留失败记录。换载荷、舵盘、连杆、末端标签或顶摄位置后，重做受影响的步骤。
