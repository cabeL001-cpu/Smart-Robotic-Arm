# 南侧路线交接说明

这份说明面向接手实车的人：怎么把车摆好、怎么跑通 `python -m move.south_route`、输出怎么读、偏了怎么调、出故障怎么查。所有命令都在树莓派的 `~/Smart-Robotic-Arm/Agents` 目录下执行，代码本身也在树莓派上运行，Windows 只用来编辑。

## 1. 这条路线做什么

车从场地左下角出发，车头朝 +X（东），执行三步：

1. 东行 73 cm，到达九宫格中线 x = 0.90 m；
2. 原地左转 85.5°（实测车头与九宫格南边平行时陀螺读 85.5°）；
3. 北行 41 cm，车头前沿**贴住**九宫格南边、不留缝。

九宫格是地上 30 cm × 30 cm 的平板，中心 `(0.90, 0.90)` m，南边 y = 0.75 m；车身长 34 cm，最终车心 `(0.90, 0.58)` m。跑道坐标系以场地左下角为原点。

直行不是一口气开完：每 400 ms 停一次，用 YbImu 的**陀螺仪积分**航向与目标比较，超过 1° 就原地小脉冲转回。转向也用同一套闭环。不用 AHRS 融合航向，原因见 `move/README.md`（磁力计被电机干扰）。

## 2. 硬件与前置条件

| 项 | 要求 |
| --- | --- |
| 底盘 | 银立方四轮，Uno 烧录 `move/` 合并固件（已含 `arm_control.ino` 和 `sonar.cpp`） |
| 蓝牙 | HC-05 配好并绑定为 `/dev/rfcomm0`，9600 8N1 |
| IMU | YbImu 接 USB，`/dev/ttyUSB0`，115200 |
| 电池 | **满电**。实测参数与电量强相关，掉电后车明显变慢 |
| 场地 | 九宫格按上述坐标摆正，起点后方与左右各留出 >30 cm 净空 |

串口是**独占**的：同一时间只能有一个程序使用 `/dev/rfcomm0`。上一条命令没退出就再开一条会报 `Could not exclusively lock`。

## 3. 上电与连接

```bash
source ~/Smart-Robotic-Arm/.venv/bin/activate
export UNO_PORT=/dev/rfcomm0

sh bt_link.sh bind                      # 树莓派重启或 HC-05 断电后需要
ls -l /dev/rfcomm0                       # 应看到绑定好的节点
```

HC-05 插在扩展板 `5V GND RX TX` 蓝牙座；运行时不要插 Uno 的 USB 数据线（与蓝牙座共用 D0/D1）。需要烧录固件时先拔 HC-05。

冒烟测试（车应立刻收到停车握手）：

```bash
python -m move stop
```

## 4. 摆车

1. 车心对准 `(0.17, 0.17)` m，车身左侧贴住场地左边界，车头朝 +X；把车摆正，不要预先转角度。
2. 保持车身**静止两秒**，程序启动时在这段时间标定 IMU 零偏和初始航向。
3. 对好九宫格：板中心 `(0.90, 0.90)` m，边与场地边平行。

> 起点方向的偏差会整体带进终点。如果车头本身朝东偏了 2°，可以在命令里把 `--turn-deg` 同向减 2° 补偿。

## 5. 跑路线

先预演，只打印路线和理论终点：

```bash
python -m move.south_route --dry-run
```

实际执行。贴板时车头会进入前探头的 300 mm 判停区，必须先临时关避障：

```bash
python -m move --avoid off
python -m move.south_route
python -m move --avoid on          # 立刻恢复；Uno 重新上电也会自动恢复
```

`--avoid off` 只改运行时开关，不会写进固件。跑完忘了恢复，重上电即可；但重上电后要重新 `sh bt_link.sh bind`。

## 6. 参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--gap-cm` | `0` | 车头前沿与九宫格南边的距离；0 为贴住 |
| `--turn-deg` | `85.5` | 原地左转角度，按实车与板边对齐测得 |
| `--east-ms` / `--north-ms` | 4760 / 2830 | 直接覆盖两段直行毫秒数 |
| `--speed` | 无 | 给出后按几何距离重算两段时长（m/s） |
| `--chunk-ms` | `400` | 直行分段，越小修正越频繁、整体越慢 |
| `--start-skip-ms` | `1600` | 东行起步先不修正的时长，等后方离边界超过 30 cm |
| `--deadband-deg` | `1` | 直行允许的航向偏差 |
| `--ms-per-deg` | `45` | 短脉冲修正的毫秒每度 |
| `--yaw-scale` | `1` | 陀螺航向比例修正，等于 90 ÷ 手推 90° 时陀螺列读数 |
| `--turn-deadband-deg` | `1` | 转向允许的偏差 |
| `--imu-port` / `--port` | `/dev/ttyUSB0` / `$UNO_PORT` | 设备节点 |
| `--calibration-s` | `2` | IMU 静止标定时间 |

默认毫秒数是 2026-11-23 满电、400 ms 分段实测的：东向 73 cm / 4760 ms（约 65 ms/cm），北向 41 cm / 2830 ms（约 69 ms/cm）。两向有效速度不同，是因为每段起步的滑行量固定，分段数越多累计多走的距离越大，所以默认直接给毫秒数而不是统一速度。

## 7. 输出怎么读

正常输出示例（节选）：

```
东行 73.0 cm（4760 ms）→ 左转 85.5° → 北行 41.0 cm（2830 ms）
理论终点 (0.90, 0.58) m，车头朝 +Y，车头前沿贴住九宫格南边。
把车放在左下角 (0.17, 0.17)、车头朝 +X，保持静止两秒。
== 东行 ==
第 1 段 400 ms，剩余 4360 ms，跳过修正
...
  航向偏差 -1.8°，右转 81 ms
...
== 原地左转 ==
  转向偏差 +83.2°，左转 3694 ms
  转向偏差 +1.2°，左转 65 ms
== 北行 ==
...
南侧路线完成，最终航向偏差 +0.4°。
```

- 每段打印剩余毫秒和该段修正后的航向偏差；`跳过修正` 是起步 1.6 s 内不做旋转，避免后方被避障拦截。
- 转向前几行是粗转（约 44.4 ms/度），后面是 45 ms/度的小脉冲。
- 最终偏差在 ±1° 内即正常。物理验收：车头前沿与板南边贴齐，车心在 x = 0.90，左右居中。

## 8. 偏了怎么调

跑一次，用卷尺量物理结果：

| 实测偏差 | 调整 |
| --- | --- |
| 东向多走 Δ cm | `--east-ms` 减 Δ×65（少走则加） |
| 北向多走 Δ cm | `--north-ms` 减 Δ×69（少走则加） |
| 车头多转 Δ° | `--turn-deg` 减 Δ（少转则加） |
| 整条路线整体左/右偏 2–3° | 起点摆放没摆正，或需要按第 9 节核对陀螺比例 |
| 每次修正都修正过头、来回摆 | `--ms-per-deg` 从 45 改小，或 `--deadband-deg` 放宽到 1.5–2 |

调到稳定满意后，把 `south_route.py` 顶部的 `EAST_MS`、`NORTH_MS`、`TURN_DEG` 三个常数改成新值并提交，下一个人直接用默认值即可。

注意：**这个参数组合只对应满电电池和这块场地**。换电池、换地面、车轮打滑都会让结果变化；每次重要验收前先跑一遍看偏差。

## 9. 核对陀螺比例与方向

车摆正、保持静止，运行：

```bash
python -m move.heading --watch
```

用手把车头转过 90°，看两列读数。陀螺列应接近 ±90°（左转为正）：

- 陀螺列稳定在 90° 附近：直接用。
- 陀螺列等比例偏（例如读 80°）：加 `--yaw-scale 90/80`（`south_route` 也支持该参数）。
- AHRS 列手停后自己走、或与陀螺列越差越多：磁力计被干扰，正常，控制器只用陀螺列。

## 10. 故障查询

| 现象 | 原因与处理 |
| --- | --- |
| `Could not exclusively lock /dev/rfcomm0` | 另一个程序占着串口。`fuser -v /dev/rfcomm0` 找到并结束它；确认没有残留的路线进程 |
| `br-connection-page-timeout`、读回 `b''`、`Input/output error` | HC-05 在射频层没响应。先查电池和车电，再断电重插模块，重新 `sh bt_link.sh bind`；节点权限用 `sudo chown $USER /dev/rfcomm0` |
| `路线中止：Write timeout` | 行驶中链路掉线。`ReconnectLink` 会关端口重开并重新停车握手（15 s 内），仍失败就终止。多为供电不足，满电重试 |
| `底盘因避障保持停车：ERR OBSTACLE FRONT 2xx` | 前方 <300 mm。贴板段必须 `python -m move --avoid off`；或移开障碍 |
| `ERR SONAR FRONT` | 前探头无有效读数（未预热、NACK、超量程）。检查探头接线；台架验证可关避障 |
| IMU 无数据 / 标定卡住 | `ls -l /dev/ttyUSB0`；YbImu 插好；启动前后车身必须静止 |
| 车走不动或明显变慢 | 电量不足，换满电电池后重新按第 8 节校正 |
| 航向修正来回小幅摆动 | 正常收敛过程；若超出 ±2° 反复不稳，按第 8 节调 `--ms-per-deg`/`--deadband-deg` |

## 11. 涉及文件

| 文件 | 作用 |
| --- | --- |
| `Agents/uno.py` | 串口层：打开、`STOP` 握手、`wait_reply`、`ReconnectLink` 断线重连（含排他锁重试） |
| `Agents/move/__init__.py` | `move()` 发动作并等 `DONE`，`avoidance()` 切避障开关 |
| `Agents/move/heading.py` | 陀螺航向、分段直行 `go_straight`、原地转 `turn_to` |
| `Agents/move/nav_sensors.py` | `open_imu()`、`ImuFeed` 陀螺积分与快照 |
| `Agents/move/imu/` | YbImu 帧解析、零偏标定、航向积分 |
| `Agents/move/south_route.py` | 本路线，含实测常数 |
| `Agents/move/README.md` | 模块总说明（避障、协议、参数） |
| `Agents/move/SOUTH_ROUTE.md` | 本文档 |

这条路线没有自动化测试，验收依据就是第 5 节的实际运行与第 7 节的物理测量。底层模块有单元测试，可在改过 `uno.py`/`nav_sensors.py` 后跑：

```bash
python -m unittest move.test_sonar move.imu.test_imu
```

（`arm.test_arm` 的 2 个失败是已知的几何改版遗留，与本路线无关，不要因此改断言。）

## 12. 注意事项

1. **串口独占**，同一时间只跑一个程序。
2. 烧录 Uno 时拔下 HC-05；运行时拔掉 USB 数据线。
3. `--avoid off` 是临时开关，跑完恢复 `--avoid on`，重上电也会恢复。
4. 转向和每次修正都会原地旋转，检查四向（尤其后方）>30 cm 净空。
5. 实标常数与电池、场地绑定，交接后第一次上电先跑 `--dry-run` 和一次实测，确认偏差再正式使用。
